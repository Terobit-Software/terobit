# terobit manifest - .tbman - v1

[common header](../common/HEADER.md) with magic `TBMN`, version `1`, then this body
encoded with postcard (see [conventions](../common/CONVENTIONS.md#body-encoding)).

## body

```rust
struct ManifestV1 {
    /// which side this pack is for. clients and servers get different packs,
    /// see tbpk. covered by the signature, so it can't be swapped.
    target: Target,
    /// the realm (game) this pack belongs to
    realm_id: u64,
    /// the developer who owns the realm
    owner_id: u64,
    /// none: anyone can run it. some: only this user can.
    /// the server enforces this for online play, the client field is only a hint.
    allowed_user: Option<u64>,
    /// version of this pack's content, bumped on every publish.
    /// the client and server pack from one publish share the same value, and online play
    /// rejects a client whose pack_version doesn't match the server's.
    /// not related to the format version in the header.
    pack_version: u32,
    /// version of the script host api the scripts were built against.
    /// lets the runtime keep old games working when the api changes.
    runtime_api: u32,
    files: Vec<FileEntry>,
    assets: Vec<AssetEntry>,
    scripts: Vec<ScriptEntry>,
}

enum Target {
    Client = 0,
    Server = 1,
}

struct FileEntry {
    /// see path rules in conventions
    path: String,
    /// uncompressed size in bytes
    size: u64,
    /// blake3 of the uncompressed bytes
    hash: [u8; 32],
}

struct AssetEntry {
    /// `namespace:name`, see conventions
    id: String,
    /// index into `files`
    file: u32,
}

struct ScriptEntry {
    /// `namespace:name`, same rules as asset ids
    id: String,
    /// index into `files`, must be a `.wasm` file
    file: u32,
}
```

## rules

readers must reject a manifest where:

- `target` isn't the reader's side (a client loading a server pack, or the reverse)
- two `files` share a path, or two paths differ only in case
- any path breaks the [path rules](../common/CONVENTIONS.md#paths-inside-a-pack)
- any `file` index is out of range
- two `assets` or two `scripts` share an id
- a script's file doesn't end in `.wasm`

`files` is sorted by path (byte order) so two builds of the same content produce identical
bytes. assets and scripts refer to files by index, so a file shared by several entries is
stored once.

## scripts

scripts are raw wasm modules. there is no terobit wrapper: wasm has its own header and
version, and everything terobit needs to know about a script (id, hash) lives here.

every script in a pack runs on that pack's `target`. there is no per-script side, because
a client pack never contains server code in the first place.

## size

for a pack with 1000 files and short paths, the manifest is roughly 60 kb, most of it
hashes. it is read once per pack load.
