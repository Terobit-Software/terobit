# terobit manifest - .tbman - v1

[common header](../common/HEADER.md) with magic `TBMN`, version `1`, then this body
encoded with postcard (see [conventions](../common/CONVENTIONS.md#body-encoding)).

## body

```rust
struct ManifestV1 {
    /// which side this pack is for. covered by the signature, so it can't be swapped
    target: Target,
    /// the realm (game) this pack belongs to
    realm_id: u64,
    /// the developer who owns the realm
    owner_id: u64,
    /// whether playing needs a license. see tblic
    access: Access,
    /// version of this pack's content, bumped on every publish. the client and server
    /// pack from one publish share the same value, and online play rejects a client whose
    /// pack_version doesn't match the server's.
    /// not related to the format version in the header.
    pack_version: u32,
    /// sorted by path, byte order
    files: Vec<FileEntry>,
    assets: Vec<AssetEntry>,
    scripts: Vec<ScriptEntry>,
    /// the pack index, which says where every file's bytes are and holds every chunk's hash
    index: IndexRef,
}

enum Target {
    Client = 0,
    Server = 1,
}

enum Access {
    /// anyone can play
    Free = 0,
    /// the client needs a valid license for this realm and the last logged in user
    Licensed = 1,
}

struct FileEntry {
    /// see path rules in conventions
    path: String,
    /// uncompressed size in bytes
    size: u64,
}

struct AssetEntry {
    /// `namespace:name`, see conventions
    id: String,
    /// index into `files`
    file: u32,
}

struct ScriptEntry {
    /// `namespace:name`, see conventions
    id: String,
    /// index into `files`, must be a `.wasm` file
    file: u32,
}

struct IndexRef {
    /// exact length of the index in bytes
    len: u64,
    /// hash(INDEX, index bytes), see integrity
    hash: [u8; 32],
}
```

file hashes aren't in the manifest. the index holds a hash for every chunk, and the
manifest holds the hash of the index, so the manifest stays small (no per-file hashes)
however large the files are.

## rules

readers must reject a manifest where:

- `target` isn't the reader's side (a client loading a server pack, or the reverse)
- any path breaks the [path rules](../common/CONVENTIONS.md#paths-inside-a-pack)
- `files` isn't strictly sorted by path (this also rules out duplicates)
- any `file` index is out of range
- two `assets` or two `scripts` share an id
- a script's file doesn't end in `.wasm`
- `realm_id` isn't the realm the reader asked for (enforced once realms exist)

## scripts

scripts are raw wasm modules. there is no terobit wrapper: wasm has its own header and
version, and everything terobit needs to know about a script lives here. every script runs
on the pack's `target`.

a script can only import from versioned host modules: `terobit_v1`, `terobit_v2`, and so on.
no wasi, no other import modules. the runtime refuses a script that imports a host module
version it doesn't have ("update terobit to play this"). one script can import from
several versions, so games can adopt new apis one function at a time, and old versions
are kept as long as published games use them. the manifest doesn't record an api version
because the imports already say exactly what a script needs.

## compression

packs whose manifest is v1 compress chunks with zstd at level 5, using the zstd version
recorded here. the version is pinned so the same content always produces the same bytes
and the same chunk hashes.

- zstd version: libzstd 1.5.7 (`zstd` `=0.14.3` and `zstd-sys` `=2.1.2` in the workspace `Cargo.toml`)
- level: 5

changing either needs a new manifest version.
